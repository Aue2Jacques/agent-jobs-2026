## 结论

### 1. 这是工程岗，不是算法岗 [统计][原文]

- 83% 的 JD 提到"落地 / 上线 / 生产 / 规模化"；"稳定性 / 可靠性"53%。
- 语言：Python 68%、Java 58%、Go 45%、C++ 41%。
- 后端基础照样考：分布式 / 高并发 26%，MySQL / Redis / MQ 26%。16 篇面经里 9 篇有手撕算法，7 篇有 OS / MySQL / Redis 八股。
- 原文例：阿里 Agent Infra 工程师要求"熟悉后端技术栈（微服务/消息队列/缓存）及云原生（K8s/Serverless）或安全隔离技术（Docker/gVisor）"。

- **"评测"和"落地"几乎和 RAG 一样高频**。

### 3. "Harness"是今年新冒出来的词，字节和 DeepSeek 在用 [统计][原文]

- 字节有 24 条 JD 出现 Harness，其中 3 个岗位直接以它命名：Flow 的"AI娱乐方向 Agent Harness 研发工程师"、国际化广告的"Agent Harness 工程师"、Data AML 的"豆包大模型 Agent Harness 算法工程师"。
- DeepSeek 专门设了"Agent Harness 团队"，原文："Model + Harness = Agent"。
- 阿里、腾讯、美团的 JD 里**一条都没有**这个词。
- 16 篇一手面经里 6 篇问到 Harness：5 篇问"怎么理解 Harness / Harness 包含哪些能力 / 解决什么问题"（字节 2、蚂蚁 1、科大讯飞 1、vivo 1），1 篇问"了解过 DeepSeek Harness 吗"（阿里云）。字节 Agent Infra 面试的追问顺序是"Agent Loop → Runtime → Harness → 框架 → Memory → MCP/Skill → Sandbox"。
- 这类 JD 有个共同的写法 [原文]："是 Agent 产品的高强度用户……深度使用过代码类及通用类 Agent 产品"（DeepSeek）；"是 AI Agent 产品的深度使用者（如 Codex、Claude Code、Cursor……）"（字节 Flow）。

### 4. 面试官追问什么 [原文，来自面经]

一手面经里反复出现的追问：

1. **为什么这么设计**：为什么用 Agent 不用规则或普通接口；为什么拆成 Planner / Executor / Critic；为什么用 LangGraph；为什么选 Markdown 做记忆而不用 RAG。
2. **怎么证明有效**："你如何证明……方案是有效的？""你的项目经过了什么样的评测？""如何分别评估召回质量和最终回答质量？"（阿里 Token Foundry 二、三面）
3. **出了问题怎么查**：长任务从 5 分钟变成 20 分钟，怎么定位（字节）；死循环、空转怎么防（阿里）；Agent Loop 的停止条件（讯飞）；上下文越来越大怎么办、压缩怎么少丢信息（字节、阿里、度小满）。
4. **离上线差多远**："企业级 RAG 与学习型 Demo 有哪些不同？"（字节二面）；"距离真正上线还有哪些工作要做？"（阿里二面）。
5. **AI 写的代码你怎么把关**：16 篇里 5 篇深挖了候选人的 AI 编程过程，其中 4 篇明确问"哪些是你写的 / AI 写的怎么验收"。如"哪些代码和设计是你亲自完成的，哪些是 AI Coding 辅助完成的？你如何验收 AI 生成的代码？"（阿里二面）；"测试用例是你给出场景约束让 AI 生成，还是 AI 自己产出？"（美团）。
6. **跟没跟前沿**："了解过 DeepSeek Harness 吗"（阿里云）；"你认为 Claude Code 哪些功能做得比较好？"（阿里三面）。

### 5. 希望看到什么项目

**JD 里直接写的** [统计][原文]：

- 72% 明确要求或优先"有 Agent 实践 / 项目 / 落地经验"。
- 42% 提到开源（项目或贡献），26% 提到"从 0 到 1 / 独立搭建 / 个人作品 / Demo"。
- 粗分（按职责全文关键词，一条 JD 可以同时属于几类）：44% 的岗位涉及**研发效能类 Agent**（代码、测试、质量、运维、诊断），40% 是业务场景 Agent（电商、广告、客服、风控、直播），29% 是 Agent Infra / 运行时 / 沙箱。
- 例：字节 TRAE 要求"理解 Agent Loop、任务分解、多轮工具调用、上下文构造、状态管理、失败恢复、结果验证、Tracing、实验评估等核心机制，能够端到端分析和优化 Agent 应用效果"。

**我的推断** [推断]：

- 面试官要的不是"做了个 Agent"，而是**能扛住三四层追问的 Agent**：有真实的使用场景、有评测数字、有失败案例和改进记录、能说清 Harness 那一层（循环、状态、上下文、工具、停止条件）怎么设计。
- "RAG + LangChain 的 demo"已经是默认项，面经里被当作基础题问，不再是亮点。这点有两篇二手总结也这么说，但它们可能是培训机构的引流帖，只当参考。
- 字节和 DeepSeek 把"深度使用 Claude Code / Codex 这类 Agent"写进了要求，说明**对现成 Agent 工具的使用深度和判断力**本身就是考察项。

## 局限

1. 样本偏字节（113/137）。阿里、腾讯、美团在官网上的"Agent 工程岗"本来就少：腾讯校招岗按大类招（如"Agent开发工程师"一个岗覆盖 6 个事业群），美团的 Agent 岗多在"北斗"算法序列。
2. 月之暗面没有公开 JD；智谱只有社招 JD；DeepSeek 是社招门户上的岗位（写明接收应届）。
3. 关键词计数是正则匹配，"评测"会把"评估"一起算进去，"落地"是很宽泛的词。数字只用来看相对高低，不能精确到个位。
4. 面经全部来自牛客，是作者自述，没法核实。16 篇一手里有 1 篇（字节广告）作者像社招，有 3 篇（阿里 Token Foundry）作者未标届别。二手总结帖里有带推广链接的，已单独列出、没算进统计。
5. 创业公司覆盖弱：除 MiniMax、面壁、DeepSeek 外，Manus、YouWare 等 agent 创业公司没找到 2027 届校招 Agent 工程岗的公开 JD。
